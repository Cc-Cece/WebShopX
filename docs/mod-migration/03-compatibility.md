# 兼容性契约

## 1. Paper 零回归契约

每个 Mxx 至少验证：

- 原有 Gradle task 名称和默认 `assemble/build` 行为不被删除；
- `plugin.yml`、Folia 元数据、命令、权限、softdepend 和 JAR 分类器保持兼容；
- 当前支持的 Java/Paper 目标仍能构建；
- `config.yml` 旧配置可启动且默认值不发生危险变化；
- SQLite/MySQL/MariaDB 旧库可升级，钱包、订单、库存、发货和支付语义一致；
- Web 路由、JSON 字段、状态码和 Relay RPC 不被无版本地破坏；
- 现有测试保持通过，新增跨平台测试不能通过跳过 Paper 路径实现。

必要的兼容性修复允许改变内部结构；外部行为变化必须有迁移说明、测试和项目所有者批准。

## 2. 数据库共享边界

可以共享：账户、身份绑定、钱包、流水、商品定义、订单、支付记录、促销、通知、审计、运行时配置及不含平台原生对象的市场数据。

必须带兼容域：物品快照、库存批次、市场实物、邮箱附件、待发货负载、离线背包操作、材质/注册表引用。

数据库规则：

- 新列必须有旧数据安全默认值；
- schema 版本单调递增；
- 多版本节点并存期间，旧节点必须能忽略新字段或被启动门禁阻止；
- migration 必须幂等并有 SQLite 与 MySQL/MariaDB 路径；
- 不允许两个平台分别维护同名但语义不同的表；
- 物品原始负载与规范化索引分离，索引失败不能毁掉原始负载。

## 3. 配置兼容

- 启动必要配置继续使用现有配置体系；业务设置继续以 admin + 数据库存储为主。
- 平台专用配置使用命名空间，例如 `platform.fabric.*`，不能重新定义共享键含义。
- 未识别的新配置由旧版本忽略；不支持的旧配置产生明确警告和迁移建议。
- 密钥只从安全配置/环境获得，导出诊断必须脱敏。

## 4. API 与 Relay

保持兼容的内容包括：URL、方法、认证、状态码、错误码、字段类型、金额单位、时间格式、分页、幂等键和 Relay 消息语义。

允许的向后兼容变化：新增可选字段、新端点、新错误详情。删除/重命名/改变类型必须发布新版本契约并保留迁移窗口。

所有平台共享契约测试；平台身份只在确有业务意义时暴露。前端不得通过 Loader 名称推断功能，应读取能力描述。

## 5. 跨平台交易

- 货币、虚拟权益和纯业务订单可以跨平台处理。
- 实物商品在创建、购买、转移和领取时都校验兼容域；不能只在最终发货时检查。
- 不兼容物品保持待领取状态并说明原因，不自动退款或删除，除非业务规则明确且幂等。
- 跨节点只有一个节点获得发货租约；完成确认以稳定操作 ID 写入。
- 节点离线、超时或结果未知时进入可恢复状态，不能重复扣款或发货。

## 6. 外部集成

- Bukkit Vault/YuPay 桥保持原样可用。
- Mod 侧通过 `EconomyProvider`、`PermissionProvider`、`PaymentProvider` 等 SPI 接入。
- Provider 缺失只禁用依赖该 Provider 的功能，启动和无关功能继续可用。
- Provider 能力、版本和事务特性在启动时注册，不能仅凭类是否存在判定完整支持。
