# ADR-0001：以最新 main 建立迁移基线

- 状态：accepted
- 日期：2026-08-22
- 决策者：项目所有者（当前对话书面指令）

## 背景

原计划创建于包含未合并促销工作的 `fd64592`，历史 Mod 原型则分叉自更早的 `a2e842c`。项目所有者明确建议以最新 `main` 为 base，并认为旧 Mod 适配已过时、不值得作为实现来源。

## 决策

- 受控迁移基线固定为 `origin/main@eca332bb8bbf723767b854cf8334c8cb1ddbe4cd`。
- 迁移计划以独立提交 `b7bfc1ba452f6d9a83936a75a340942a1d3f075b` 叠加在该基线上。
- `feat/fabric-neoforge-mod` 只作为拒绝复用的历史证据，不 cherry-pick、不复制实现、不继承状态。
- 未合并的促销分支和相邻前端工作区修改不进入迁移基线；后续若经正常流程进入 `main`，通过普通 merge 同步到 `mod-integration` 并重新运行 Paper 门禁。

## 理由

历史原型基于旧业务模型，并删除或改写了大量当前服务、API、数据库和资源。整体复用会把过期行为带回正式线，无法证明 Paper 零回归。以最新正式主线重新定义端口和适配器，可让每次迁移都有当前行为测试作为依据。

## 后果

- M1–M8 的 Loader 代码从受控契约重新实现，开发成本高于修补旧原型，但回归边界清晰。
- 当前未合并业务不会被擅自纳入范围；它们合并到 `main` 后属于必须同步的新基线能力。
- 任何声称来自历史原型的实现都必须重新提出 ADR；本 ADR 默认拒绝该路径。

## 回退

删除迁移分支即可回到 `origin/main@eca332b`；本决策不修改生产数据、外部 API 或正式发布线。
