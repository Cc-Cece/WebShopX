# M7：现代版本收口与客户端增强决策

## 目标

收口数据组件时代的跨版本行为，并用证据决定是否发布可选 WebShopX 客户端附属 Mod；无论结论如何，服务端核心保持完整。

## 现代版本任务

- 对比 Fabric/NeoForge 的注册表、数据组件、网络和容器 API；
- 固化 legacy NBT → modern component 的允许转换白名单；
- 对不可无损转换内容保持原兼容域并拒绝跨域领取；
- 验证现代原版和代表性 Mod 物品、Bundle/潜影盒及嵌套限制；
- 建立新 Minecraft 版本接入清单：依赖冻结、编译、fixture、server smoke、功能矩阵。

## 客户端决策探针

比较两种路径：

- 服务端标准容器 + Web/命令；
- 可选客户端增强：自定义屏幕、物品预览、快捷交互。

记录用户价值、三 Loader/版本成本、网络协议、安全、无客户端降级和维护成本。只有 ADR 接受后才建立客户端模块。

## 客户端约束

- 不能把扣款、价格、权限、库存或发货判断放到客户端；
- 服务端协商协议版本和 capability；
- 未安装、版本不匹配或包被篡改时回退到完整服务端路径；
- 客户端包独立命名、依赖和 CI；不得误装到 dedicated server 必需列表。

## 验收

- modern 版本全功能与物品测试通过；
- 跨 legacy/modern 的允许与禁止矩阵清晰且可执行；
- 客户端结论有 ADR，不以个人偏好决定；
- 如果实现客户端，三个 Loader 的承诺范围、协议测试和无客户端路径通过；
- Paper 与旧 Mod 线不回归。
