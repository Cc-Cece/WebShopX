# 程序员 Agent 执行手册

## 1. 开始一次任务

1. 完整阅读 `docs/mod-migration/README.md` 指定文件；
2. 查看 `task-status.md`，只选择前置条件已满足的首个任务；
3. 获取最新 `mod-integration`，确认无未解释的本地修改；
4. 创建 `feature/Mxx-<topic>`，不得在共享分支实施；
5. 运行 M0 固化的最小基线门禁；
6. 检查当前代码、调用链、测试、配置、资源和历史 ADR，禁止只按任务文件猜代码；
7. 在 PR 草稿或实现报告记录开始 commit 和环境。

## 2. 实施方式

- 先用 characterization test 固定待迁移行为，再改变结构。
- 一次迁移一个边界；Paper 先改为调用新接口并通过，再增加 Mod 实现。
- 公共模块不得出现 Loader/Minecraft 类、条件编译标记或反射类名。
- 数据和物品路径先写失败/恢复测试，再写成功路径。
- 对发现的更优方案进行验证；在授权范围内可直接采用并写 ADR。
- 发现任务描述与真实代码不符时，修正文档/ADR，不得机械制造不存在的类。

## 3. 验证

每次有意义的提交运行受影响测试；PR 前运行任务全部门禁和 Paper 回归。记录完整命令、退出码、跳过项、环境和日志/报告路径。“机器没有环境”不是跳过而不记录的理由。

真实服务器 smoke 使用临时目录、动态端口和测试凭据；不得读取生产配置。构建缓存可用于开发，但至少一次 Release gate 使用干净依赖/输出验证。

## 4. 实现报告

放入 `implementation/reports/Mxx-implementation.md`，内容包括：

- 基线和最终 commit；
- 实际范围/非范围；
- 关键设计与 ADR；
- 文件、schema、API、配置和依赖变化；
- 验证环境、命令、结果和证据路径；
- Paper 等价证据；
- 风险、已知限制和回退；
- 与计划偏差及理由；
- 请求审核的固定 PR head SHA。

## 5. 审核后的处理

- `accepted`：由有权限的非审核 Agent 合并到 `mod-integration`；
- `accepted_with_notes`：非阻塞意见进入 backlog，除非修复极小且不改变审核范围；
- `changes_required`：只处理列出的阻塞问题并追加提交，提供闭环证据；
- `blocked`：补齐缺失证据/决定后继续同一审核闭环。

不得要求审核者第二次全面寻找新问题。修复若产生新 P0/P1 风险，审核者可以只扩展到该风险。

## 6. 收尾

合并后更新 `task-status.md` 的真实 merge commit 和审核结论。不要提前把任务写成 completed。清理只限自己的临时目录；不得删除他人的工作树或历史分支。
