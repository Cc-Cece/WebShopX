# 发布、迁移与回滚

## 1. 发行物

每个 JAR 文件名必须包含 WebShopX 版本、平台、Minecraft 精确版本/兼容族和 `full/slim` 等既有变体信息。发行清单记录 SHA-256、Java、Loader、依赖模式、Git commit 和构建时间。

插件放入 `plugins/`，Mod 放入 `mods/`。启动时若检测同一实例同时加载 Paper 与 Mod 入口，默认拒绝启动，避免双服务图和重复任务。

## 2. 升级前

- 停止写流量或进入维护模式；
- 备份数据库、插件/Mod 数据目录、配置、上传资源和当前 JAR；
- 验证备份可读并记录 hash；
- 检查目标节点兼容域、Modpack 和 Provider；
- 在生产副本执行 schema dry-run、迁移和对账；
- 明确回滚是否需要数据库 forward-fix，禁止假定降级二进制能读取新 schema。

## 3. 灰度

默认按测试节点 → 单个非关键节点 → 部分节点 → 全部节点推进。每阶段检查：启动/迁移、登录、下单、扣款、发货、重复请求、Relay、Redis、错误率、延迟和 tick。任何 P0/P1 立即停止扩大。

## 4. 插件与 Mod 切换

- 使用同一 `server-id` 切换前必须确保旧进程完全停止、租约过期/释放；
- 首次切换先禁用物品写入，只验证业务读与 capability；
- 兼容域变化时已有物品保持原域，不能批量重写；
- 完成受控领取、退款和补单后再开放全部流量；
- 切回插件时同样执行迁移兼容与租约检查。

## 5. 回滚触发

包括但不限于：余额/流水不一致、重复发货、物品损坏、migration 无法完成、节点持续崩溃、认证/权限绕过、Relay 重放、严重 tick 回退。

## 6. 回滚动作

1. 进入维护模式并保存诊断；
2. 停止新交易和发货 worker；
3. 确认正在处理操作的最终状态，标记未知结果待对账；
4. 停止新版本节点；
5. 按演练结论恢复旧二进制或执行 forward-fix；
6. 只有在确认迁移不可逆且获得所有者授权时恢复数据库快照；
7. 对账钱包、流水、订单、库存、邮箱和操作 ID；
8. 记录事故与后续 ADR。

不得在仍有新写入时直接恢复旧数据库快照。

## 7. 正式发布权

Agent 可以构建候选包、生成 Release PR 和 `release_recommended` 等意见，但不得合并 `main`、打正式 tag、创建/修改正式 Release 或上传正式渠道。全部由项目所有者决定。
