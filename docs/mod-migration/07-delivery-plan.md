# 交付计划与依赖

## 1. 阶段表

| 阶段 | 主要结果 | 前置 | 可并行内容 | 合并门禁 |
|---|---|---|---|---|
| M0 | 当前基线、功能/API/数据清单、历史原型审计 | 计划获批 | 只读取证 | 基线可复现 |
| M1 | 多模块、版本目录和最小 Loader 启动 | M0 | Loader 构建探针 | Paper 产物不变 |
| M2 | core 抽取、Paper adapter、共享契约测试 | M1 | 纯业务分批迁移 | Paper 功能等价 |
| M3 | 平台端口、物品信封、线程/库存契约 | M2 | codec fixture | 合同测试通过 |
| M4 | Fabric 范围内全功能 | M3 | 各版本族 adapter | Fabric 验收通过 |
| M5 | Forge 1.18.2–1.20.1 全功能 | M3 | 可与 M4 后段并行 | Forge 验收通过 |
| M6 | NeoForge 1.20.1–最新全功能 | M3 | 可与 M5 后段并行 | NeoForge 验收通过 |
| M7 | 现代版本、GUI 与可选客户端结论 | M4/M6 | 客户端探针 | 降级路径完整 |
| M8 | 共享 DB/Redis/Relay、生态 Provider、混合集群 | M4–M7 | Provider adapter | 故障与一致性验证 |
| M9 | CI 全矩阵、迁移/回滚、RC 产物 | M8 | 文档与演练 | Release readiness |

默认串行推进 M0–M3；M4–M6 只有在不同分支、契约已冻结且合并冲突可控时并行。一个 Agent 不得用“并行中”跳过前置门禁。

## 2. 阶段变更

允许把 Mxx 拆成 `Mxx-a/b` PR，但只有全部子项通过后才能正式审核 Mxx。允许因新证据调整内部步骤；改变范围、顺序依赖或验收标准需要 ADR。缩小产品范围需要项目所有者批准。

## 3. 每阶段共同交付物

- 实现代码和迁移；
- 自动测试及真实启动证据；
- 实现报告；
- 更新支持矩阵、能力矩阵和 task status；
- 必要 ADR；
- 一次正式审核报告；
- 可回退的 Git 历史。

## 4. 缺陷优先级

- P0：数据丢失、复制、任意权限绕过、远程执行或秘密泄露；立即停止合并。
- P1：扣款/发货错误、迁移失败、平台无法启动、Paper 回归；阶段阻塞。
- P2：有安全替代路径的功能故障、显著兼容或性能问题；正式 Release 前必须处理或由所有者批准例外。
- P3：不影响正确性的体验、日志或维护性问题；可记录后续任务，不强制提出建议。

## 5. 时间与成本

计划不写死周数。每阶段完成 M0 盘点后估算“适配器数量 × 版本族 × 验证环境”。任何时间压力都不能自动降低数据安全、Paper 回归或正式版功能等价门槛。
