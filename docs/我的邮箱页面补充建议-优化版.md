# “我的邮箱”页面补充建议

> 目标：在保留当前页面结构和视觉风格的基础上，补齐领取、退款、状态管理及物品展示能力。

## 1. 当前页面可保留

当前页面已经具备：

- 搜索；
- 领取状态筛选；
- 退款状态筛选；
- Mailbox 托管说明；
- 商品、来源、数量、退款资格及当前状态展示；
- 展开查看创建时间、退款截止时间及进入邮箱原因；
- 单条退款入口。

整体结构合理，无需大幅重做，后续以补充功能和优化交互为主。

## 2. 建议优先补充

### 2.1 顶部状态汇总

在筛选区上方增加简洁的状态统计：

- 待领取；
- 可退款；
- 即将到期；
- 领取失败。

点击统计项后，直接应用对应筛选条件。

### 2.2 明确的快捷操作

每条邮箱记录建议提供以下操作：

- `领取`；
- `申请退款`；
- `查看订单`。

#### 领取规则

- 玩家在线时：尝试将物品直接放入玩家背包，或执行对应权益、命令和效果；
- 玩家离线时：
  - 若“离线背包即时管理”关闭，则提示玩家上线后领取；
  - 若“离线背包即时管理”开启，则在完成锁定、在线状态复查、备份和原子写入后，将物品写入离线背包；
- 背包空间不足、目标服务器不可用或执行失败时，保留邮箱内容并显示具体失败原因；
- 领取操作必须具备幂等保护，避免重复发放。

“离线背包即时管理”应默认关闭，并由管理员明确开启。

#### 申请退款

点击后进入退款确认弹窗，不得直接执行退款。

#### 查看订单

跳转到“我的订单”中的对应订单或交易详情。

### 2.3 退款确认弹窗

点击退款后，应先显示：

- 商品名称；
- 本次退款数量；
- 已领取数量；
- 退款金额及货币；
- 退款后对应内容将从邮箱移除的说明；
- 动态价格商品按原成交金额计算退款的说明。

按钮：

```text
取消
确认退款
```

提交期间应同时锁定领取与退款操作，避免并发执行或重复请求。

### 2.4 退款时间显示优化

列表中优先显示易理解的退款时间状态：

- `剩余 08:42`；
- `不限时间`；
- `退款期限已结束`。

展开详情中继续保留完整退款截止时间。

### 2.5 订单与来源跳转

来源编号应可点击，并跳转到对应订单或交易详情。

支持的来源包括：

- 官方商城订单；
- 玩家市场交易；
- 拍卖结算；
- 系统补发。

普通用户只能看到可理解的商品或权益名称，不应看到真实后台命令内容。例如显示“VIP 权益”或“命令奖励”，而不是具体执行命令。

## 3. 建议补充筛选与排序

在保持页面简洁的前提下增加：

- 内容类型：物品 / 权益 / 效果 / 系统补发；
- 来源：官方商城 / 玩家市场 / 拍卖 / 系统；
- 排序：最新进入邮箱 / 退款即将到期。

筛选项较多时应使用下拉选择，不再继续增加横向按钮组。

## 4. 展开详情建议补充

展开区域建议展示：

- 原始数量；
- 已领取数量；
- 剩余数量；
- 可退款数量；
- 预计退款金额；
- 退款期限；
- 商品退款策略；
- 是否允许部分退款；
- 进入邮箱原因；
- 上次领取失败原因；
- 查看订单按钮。

仅在字段存在且有实际意义时显示，避免空字段堆积。

## 5. 状态与操作规则

| 状态 | 用户可操作 |
|---|---|
| 待领取 | 领取、退款、查看订单 |
| 部分领取 | 领取剩余部分；符合政策时退款剩余部分 |
| 退款已过期 | 领取、查看订单 |
| 商品禁止退款 | 领取、查看订单 |
| 领取失败 | 查看失败原因、重新领取、查看订单 |
| 退款处理中 | 仅查看，暂时禁用领取 |
| 领取处理中 | 仅查看，暂时禁用退款 |
| 已领取 / 已退款 | 查看详情、归档 |

待领取记录不得提供“删除”操作。已结束记录只能归档，不能删除业务数据。

## 6. 接入已有资源

“我的邮箱”应直接复用系统现有的物品展示资源，不再单独实现一套图标、名称翻译或容器预览逻辑，以保证邮箱、背包、商城和玩家市场中的显示结果一致。

### 6.1 材质图标

邮箱列表和详情应接入现有材质图标系统，支持：

- 原版 Minecraft 材质图标；
- 自定义图标；
- 自定义模型数据；
- Item Model；
- 图标缺失时的统一回退图标。

同一物品在背包、商城、市场和邮箱中应显示相同图标。

### 6.2 物品名称与多语言

物品名称应使用现有的本地化名称解析逻辑，不直接将材质 ID 作为主标题。

建议名称优先级保持一致：

1. 物品自身的自定义名称；
2. 管理员配置的显示名称；
3. 商品或市场条目的显示名称；
4. 当前语言的 Minecraft 材质名称；
5. 英文材质名称；
6. 格式化后的材质 ID。

展示示例：

```text
红色潜影盒
RED_SHULKER_BOX
```

切换语言后：

```text
Red Shulker Box
RED_SHULKER_BOX
```

材质 ID 可作为次要信息保留，但不能替代本地化名称。

### 6.3 物品属性展示

详情区域应复用现有物品属性展示能力，包括：

- Lore；
- 附魔；
- 存储附魔；
- 自定义模型数据；
- 物品模型；
- 其他可识别的 ItemMeta 信息。

对于权限、命令、效果等非实体物品，可使用统一的代表图标和用户可理解的名称，不展示内部执行细节。

### 6.4 潜影箱与容器预览

当邮箱中的物品包含容器内容时，应接入现有容器预览能力：

- 潜影箱按 9 × 3、共 27 格展示；
- 收纳袋按现有列表形式展示；
- 显示内部物品图标、名称和数量；
- 点击内部物品可查看附魔、Lore 等详细信息；
- 内部物品仍为容器时，允许继续下钻预览；
- 没有容器内容时，不显示无效的预览入口。

列表中可通过悬停或点击图标显示快速预览；展开详情后可提供更完整的预览区域。

### 6.5 数据要求

为支持已有展示资源，邮箱条目至少应提供或能够解析：

```ts
material
displayName
iconUrl
itemMetaJson
customModelData
itemModel
```

实体物品的数据应来自真实物品快照，不能只保存材质名和数量。

容器数据应包含槽位及内部物品信息，例如：

```json
{
  "material": "RED_SHULKER_BOX",
  "amount": 1,
  "containerItems": [
    {
      "slot": 0,
      "item": {
        "material": "DIAMOND",
        "amount": 32
      }
    }
  ]
}
```

### 6.6 国际化要求

- Minecraft 材质名继续使用已有的专用材质语言资源；
- 页面按钮、状态、提示和说明继续使用现有界面国际化系统；
- 所有新增界面文本必须同时补充中文和英文；
- 不得在页面组件中新增独立的中英文映射；
- 不得为邮箱单独维护材质名称翻译表。

## 7. API / 数据字段补充

建议补充或确认以下字段：

```ts
refundAmount
refundCurrency
refundDeadline
refundReason
refundPolicy
partialRefundAllowed
sourceOrderNo
sourceRoute
lastDeliveryError
deliveryInProgress
refundInProgress

material
displayName
iconUrl
itemMetaJson
customModelData
itemModel
```

退款 API 必须返回具体失败原因，例如：

```text
REFUND_EXPIRED
REFUND_DISABLED
PARTIAL_REFUND_NOT_ALLOWED
ALREADY_DELIVERED
REFUND_IN_PROGRESS
NO_REFUNDABLE_QUANTITY
```

领取 API 也应返回明确错误，例如：

```text
PLAYER_OFFLINE
OFFLINE_DELIVERY_DISABLED
INVENTORY_FULL
TARGET_SERVER_UNAVAILABLE
DELIVERY_IN_PROGRESS
ALREADY_DELIVERED
DELIVERY_FAILED
```

前端应根据错误码显示具体说明，而不是统一显示“退款失败”或“领取失败”。

## 8. 验收重点

- Mailbox 未领取不等于已经最终交付；
- 退款期限为空时正确显示“不限时间”；
- 已领取部分永远不能参与普通退款；
- 领取和退款不能并发成功；
- 重复点击领取不会重复发放；
- 离线背包即时管理默认关闭；
- 离线写入必须经过锁定、在线状态复查、备份和原子替换；
- 退款金额按原订单实际成交金额计算；
- 同一物品在邮箱、背包、商城和市场中显示一致；
- 材质图标、自定义模型、物品名称、附魔和 Lore 不丢失；
- 潜影箱、收纳袋及嵌套容器可以正常预览；
- 所有新增界面文本均接入现有国际化资源。
