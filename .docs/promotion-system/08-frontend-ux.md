# 前端与交互规格

## 1. 前端基线

目标仓库是后端相邻目录 `../webshopx-web`。开始前完整阅读其 `AGENTS.md`。当前技术栈：Vue 3、TypeScript、Vite、Vuetify、Vue Router、Axios、Vue I18n。

必须复用：

- `src/api/client.ts` 的请求/认证模式；
- `src/api/app.ts`, `admin.ts`, `shop.ts` 的 API 分层风格；
- `AppCard`, `AppDialog`, `AppToast`, `AppEmptyState`, `AppFilterBar`, `AppActionGroup`；
- `SnapshotItemIcon` 等 Minecraft 物品展示；
- 现有 currency meta 和价格格式工具；
- 现有 `AdminGate`、主题和响应式布局。

不要把新功能做成与现有商城/市场视觉和交互割裂的第二套应用。

## 2. 信息架构

### 2.1 玩家端路由

- `/shop`：官方商城，增加到手价、领券和加入购物车。
- `/market`：玩家市场，增加卖家/平台优惠和加入购物车。
- `/cart`：购物车。
- `/checkout`：结算报价与确认。
- `/orders`：父交易视图兼容旧订单。
- `/coupons`：我的优惠券。
- `/membership`：会员中心。
- `/seller/promotions`：玩家卖家促销中心。
- `/account`：增加会员摘要与优惠券入口。
- `/result`：充值结果增加优惠/奖励信息。

### 2.2 管理端路由

可以新增独立 `/admin/marketing`，或在现有 `/admin/commerce` 增加清晰二级入口；推荐独立页面避免单文件继续膨胀。子标签：活动、券、集合、人群、会员、卖家限制、资金、模拟器、报表。

权限不可见时隐藏入口，但服务端仍必须校验。

## 3. API 与类型层

新增或拆分：

```text
src/api/cart.ts
src/api/checkout.ts
src/api/promotions.ts
src/api/membership.ts
src/api/sellerPromotions.ts
src/api/adminMarketing.ts
src/types/commerce.ts
src/types/promotion.ts
src/types/membership.ts
```

如果项目倾向集中在 `app.ts/admin.ts`，可以保持，但必须避免页面直接调用 axios 和重复类型。

稳定金额类型至少包含 `currencySpace`, `currency`, `amount`；前端不做可信价格重算，只格式化服务端结果。

## 4. 购物车入口

- 全局导航显示购物车图标和商品数量；未登录点击引导登录。
- 商品卡保留“立即购买”，新增“加入购物车”。
- 立即购买可以添加到临时选择并进入 checkout，但仍调用统一报价。
- 加入成功使用 toast 和可撤销/去购物车操作；避免强制跳转。
- 市场挂单售罄或数量不足时按钮状态及时刷新。

## 5. 购物车页

### 5.1 布局

- 按官方商城、玩家卖家分组；组内显示币种、卖家名、优惠提示。
- 行包含选择框、图标、标题、来源、单价、数量、预计到手价、交付方式、状态和删除。
- 桌面端右侧固定结算摘要；移动端底部 sticky 汇总栏。
- 双币分别显示小计和余额，不显示一个混合“总价”。

### 5.2 交互

- 数量修改防抖提交并使用 cartVersion；冲突时合并最新服务端数据并提示。
- 无效行保持显示，禁用选择，提供刷新/删除。
- “全选”只选择当前可结算行。
- 满减提示以简单句展示，例如“本卖家商品再加 20 商城币，可减 10”。
- 不为追求优惠自动添加商品或改变数量。

## 6. 结算页

### 6.1 默认视图

用户进入即请求 `AUTO_BEST` 报价。展示：

- 按子单分组的商品；
- 卖家优惠、平台优惠、会员优惠；
- 每币种基础金额、优惠、费用和应付；
- 钱包余额及不足提示；
- 后置奖励；
- “系统已为你选择最优惠方案”。

主按钮文案包含要支付的各币种；若双币无法简洁放入按钮，在按钮上方清晰列出，按钮用“确认支付”。

### 6.2 更换优惠

折叠区/底部抽屉：

- 已选优惠；
- 可替代组合及节省金额；
- 可用券；
- 不可用券和人类可读原因；
- 恢复“自动最优”。

不要把内部 P1/P2、槽位或 rule ID 暴露给普通用户。

### 6.3 价格变化

提交返回 replacement quote 时，展示差异：哪件商品、原价/新价、优惠变化、总应付变化。用户主动再次确认。若只是更便宜，也展示变化并要求确认，保证行为一致。

### 6.4 防重复

点击后禁用并显示进度；idempotencyKey 在本次确认生命周期内固定，页面重试复用。刷新后可通过订单查询恢复成功结果。

## 7. 商品列表与详情

### 7.1 价格

- 基础价划线只在确有优惠时展示；不能伪造原价。
- 预计到手价比基础价突出。
- 数量相关优惠使用当前默认数量计算并注明。
- 动态价格、会员专享、卖家券、平台补贴使用不同但一致的标签。

### 7.2 优惠面板

- 自动优惠摘要；
- 可领券，按钮有领取中/已领取/领完/不符合；
- 会员提示和去开通；
- 规则详情对话框；
- 领券后重新获取预计价。

## 8. 我的优惠券

- 四状态标签页；支持来源/即将过期筛选。
- 券卡显示平台或卖家、金额/折扣、门槛、有效期、作用范围和叠加摘要。
- “去使用”跳转到对应官方商品、市场卖家/挂单或充值页面。
- 不可用原因优先显示最可行动的一项。
- 到期时间同时提供机器可读 `datetime` 和本地化文本。

## 9. 会员中心

- 当前会员卡：计划、等级、有效期、来源和状态。
- 权益列表：价格、券、叠券、费用、回收/充值等，明确适用范围。
- 可购买计划：价格、期限和“加入购物车”。
- 兑换入口。
- 历史会员和管理员授予来源只展示用户适合看到的信息。
- 会员商品退款/撤销规则在购买前可见。
- 不默认提供自动续费开关。

## 10. 卖家促销中心

### 10.1 首页

- 平台是否允许卖家促销；
- 正在进行、即将开始、已结束；
- 促销成交、让利、用券和剩余预算；
- 创建促销按钮。

### 10.2 创建

第一步只显示模板卡：单品直降、满减、满折、卖家券。之后选择自己的挂单、填写优惠/时间/预算/次数。

右侧/底部实时示例：

```text
买家原价 100
买家预计支付 90
你承担优惠 10
预计手续费 4
你预计收到 86
```

高级设置折叠。发布前调用服务端模拟，不在浏览器复制公式。

### 10.3 资源隔离

列表和选择器只加载自己的挂单；即便篡改请求也由服务端拒绝。平台活动在卖家页只读展示其影响。

## 11. 管理端营销工作台

### 11.1 活动列表

筛选状态、业务域、所有者、时间、规则类型；列出预算、消耗、订单和成本。提供暂停/恢复/修订，不提供已发布规则直接编辑。

### 11.2 创建向导

使用产品规格的九步向导。每步：

- 有安全默认值；
- 校验错误靠近字段；
- 高级字段有解释；
- 离开时保存草稿；
- 最后显示用户/卖家/平台三方金额模拟。

### 11.3 会员管理

计划/等级、期限、购买商品、权益包、周期券、退款策略。用户会员详情支持授予、续期、升级、撤销，必须填写原因。

### 11.4 资金与核对

按币种显示预算 limit/reserved/consumed/released/refunded，支持通过 checkoutNo 核对。禁止直接编辑 consumed；预算调整走审计操作。

### 11.5 紧急控制

有权限者可暂停所有新优惠结算。对话框说明：历史订单和退款仍按快照工作；已领取券不删除。

## 12. 订单页与退款

- 父交易卡显示多个子单和双币汇总。
- 展开行显示基础价、卖家优惠、平台优惠、费用、实付和交付状态。
- 退款预览先显示将退钱包、将返券、卖家/平台资金处理和不会返还的权益。
- 人工处理状态明确显示，不伪装退款完成。
- 旧订单没有价格快照时继续使用旧展示，标记“历史订单”。

## 13. 回收、收购、拍卖与充值

- 回收/收购对话框把“基础可得”和“额外奖励”分开。
- 拍卖出价页明确个人券不影响出价；成交费用权益在说明中展示。
- 充值页把法币原价、实付、基础到账、赠送到账分开；支付创建后不再允许换券。
- 支付结果页显示优惠消费/释放和奖励到账状态。

## 14. 状态与加载

所有页面必须覆盖：首次加载、局部刷新、空数据、权限不足、网络错误、版本冲突、报价过期、提交中、成功、失败和人工处理。

不要用全屏 spinner 掩盖已加载数据；优先局部 skeleton/按钮 loading。关键失败提供重试，但保持同一 idempotencyKey。

## 15. 国际化

严格遵守前端 `AGENTS.md`：

- 玩家端放 `src/i18n/app/en-US.json` 与 `zh-CN.json`；
- 管理端放 `src/i18n/admin/en-US.json` 与 `zh-CN.json`；
- 语义 camelCase key；
- 完整句子翻译，参数集合一致；
- API 枚举映射为本地化显示，不翻译传输值；
- 错误 code 映射 i18n，message 仅诊断回退；
- 动态枚举补充 `scripts/check-i18n.mjs` 合同。

后端插件/Minecraft 消息如新增，同步更新 `messages.zh-CN.yml` 和 `messages.en-US.yml`，并通过现有审计脚本。

## 16. 无障碍与响应式

- 所有图标按钮有本地化 aria-label/tooltip。
- 颜色不能是优惠来源/状态的唯一表达。
- 键盘可完成购物车选择、券切换、对话框和管理向导。
- 焦点在对话框关闭后返回触发器。
- 金额变化使用可感知状态提示但避免频繁 screen reader 噪音。
- 手机端不横向依赖大表格；管理表提供卡片或可滚动策略。

## 17. 前端验证

完成每批相关改动后，至少运行：

```text
pnpm run i18n:scan
pnpm run i18n:check
pnpm run type-check
pnpm run build
```

启动 dev server 后按可用浏览器验证技能/工具完成：商城加入购物车、市场加入购物车、双币结算、换券、会员购买、卖家促销、管理员模拟、订单退款。测试桌面与移动宽度，检查控制台、网络失败和刷新恢复。
