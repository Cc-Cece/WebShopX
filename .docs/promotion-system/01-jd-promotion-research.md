# 京东优惠体系研究

> 研究目标不是复制京东产品，而是从公开规则中提炼可验证的通用模型。京东未公开内部优惠引擎、最优组合算法或完整商家配置数据结构；涉及内部实现的内容一律标记为 `INFERENCE`。

## 1. 核心发现

### 1.1 优惠并非只有“券”

`JD-FACT` 京东公开的预估到手价范围同时包含单品直降、总价满减/满折、礼金、会员折扣、店铺/品类券、津贴与预售优惠。这说明面向用户的最终价格是多层优惠共同计算的结果，而非“商品价格减一张券”。参见来源 S2。

`INFERENCE` 一个可维护的优惠系统需要先区分价格层、促销层、券层、权益抵扣层，再定义跨层关系。仅用券类型枚举无法表达完整价格链。

### 1.2 普通规则以“商品行是否重叠”为核心

`JD-FACT` 同一订单的同一商品上，普通店铺券、限品类券和全品类券通常只能使用一张；系统优先使用优惠力度更大的券。不同券覆盖的商品范围完全不重叠时，可以在同一订单分别生效。参见来源 S1。

`INFERENCE` 叠加判断的最小单元应是订单商品行，而不是整张订单。两张券可以共处一单，不等于可以同时作用于同一商品。

### 1.3 特殊用户通过“特殊场景”突破普通互斥

`JD-FACT` 京东公开规则明确写出，PLUS 专享等特殊场景不受普通券“同一商品只能一张”的限制。新人券仅限首单且只能使用一张；品类新客资格来自该用户是否购买过对应品类。首购礼金也只对未在对应店铺下单的用户提供。参见来源 S1、S5、S6、S7。

`INFERENCE` 少部分用户获得深度优惠，适合建模为：资格规则授予某个叠加策略或特殊权益，而不是修改普通券的全局规则。

### 1.4 优惠存在明确的顺序和基数

`JD-FACT` 京东公开券规则描述了店铺券、限品类券、全品类券的处理顺序；部分满减/满折券的门槛基数使用商品金额或参加总价促销前、单品促销后的金额。参见来源 S1、S8、S9。

`INFERENCE` 每条优惠必须声明两个不同概念：

- `threshold_basis`：用哪个价格阶段判断是否满足门槛；
- `discount_basis`：用哪个价格阶段计算优惠金额。

若只存“满 100 减 20”，叠加后无法确定应按原价、活动价还是前序优惠后的价格判断。

### 1.5 优惠组合需要择优，但必须允许解释

`JD-FACT` 同商品上的互斥券由系统选择优惠力度更大者；商品页的预估到手价是系统根据当前促销和可领、可用券自动计算的结果，最终以结算页为准。参见来源 S1、S2。

`INFERENCE` WebShopX 应提供确定性的最优组合搜索，并返回被淘汰优惠的原因。只显示“不可用”会让用户和管理员无法排查门槛、范围或互斥问题。

### 1.6 售后以实际支付为基础，券是否退回是另一问题

`JD-FACT` 京东退款按实际支付金额处理；订单取消与售后退货对优惠券的返还条件不同，部分场景要求全部商品退货才返券，运费券退货后通常不返。历史规则还展示了按商品售价占比分摊支付金额的做法。参见来源 S1、S3、S4、S10、S11。

`INFERENCE` “退款金额”和“恢复优惠权益”必须分成两个状态机：退款应基于订单冻结的实付分摊；退券则根据券模板的返还政策决定。

### 1.7 特殊补贴可以独占

`JD-FACT` 部分政府/以旧换新补贴明确不能与店铺券、品类券、京券、京贴等共同使用；价保也会排除支付优惠、部分补贴、秒杀和限量券。参见来源 S12、S13。

`INFERENCE` 优惠需要具备 `EXCLUSIVE` 独占能力，并可单独声明是否参与价保，不应默认所有优惠都可叠加或参与比价。

### 1.8 风控身份不等于账号

`JD-FACT` 新人和品类新客规则会综合账号、手机号、设备或其他身份关联判断同一用户；违规时可取消资格、作废优惠和取消订单。参见来源 S6、S14、S15。

`INFERENCE` WebShopX 初期可用 `user_id + mc_uuid` 作为资格主体，但数据模型应保留 `subject_type/subject_key`，避免未来多账号绕过领取与使用限制。

## 3. 叠加机制的工程抽象

下列内容为 `INFERENCE`，并非京东内部字段名称。

### 3.1 五个决定维度

1. **作用域**：全场、商品集合、单商品、商品类型、渠道、服务器或用户。
2. **价格层**：基础价、单品促销、订单促销、券、会员权益、余额抵扣。
3. **冲突关系**：独占、同层择优、同商品互斥、作用域不重叠可共存、白名单组合。
4. **用户资格**：会员、新人、回流、标签、白名单、管理员补偿对象。
5. **财务护栏**：预算、库存、最大减免、最低实付、用户/设备/周期次数。

### 3.2 “少部分人叠券”的推荐表达

```text
普通规则：NORMAL_COUPON_SLOT，每个商品行最多占用 1 次

会员专享券：
  requires entitlement = MEMBER_STACKING
  occupies slot = MEMBER_COUPON_SLOT
  compatible_with = NORMAL_COUPON_SLOT

管理员补偿券：
  requires grant to a concrete user
  occupies slot = COMPENSATION_SLOT
  compatible_with = [NORMAL_COUPON_SLOT, MEMBER_COUPON_SLOT]
  max_discount + min_payable 仍然生效
```

这样，特殊用户只能叠加其实际拥有且被允许的券，不能把任意两张普通券组合起来。

## 4. 规则演变与资料局限

- 来源 S11 明确标注“2021 年 12 月 4 日前生效”，只能作为历史材料。旧版“京券/东券”分类和退券规则不得直接照搬。
- 京东帮助页可能持续更新但不一定展示清晰的修订时间。本文记录调研基准日，实施前若要声称与京东现行规则一致，应再次核查。
- 京东针对具体活动、商品、渠道、区域和账户的结算规则可能覆盖通用帮助规则。
- 本研究未使用京东内部资料，也未执行购买、退款或规避资格限制的实验。
- WebShopX 是单一运营方的游戏商城，不需要机械复制店铺、物流、税费和跨境概念；应复用其规则思想而非界面名词。
