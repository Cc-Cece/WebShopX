# WebShopX 优惠系统文档集

> 文档版本：1.0
> 调研基准日：2026-08-13
> 状态：待评审、可用于后续实施
> 目标：先确定完整、可解释的优惠规则，再进入代码实现。

## 1. 结论

WebShopX 应建设统一的“价格与优惠引擎”，而不是在下单接口里增加一个优惠券金额字段。引擎必须统一处理商品价、促销、优惠券、用户权益和抵扣，并生成不可变的价格快照，使预览、下单、幂等重试和退款使用同一套事实。

“允许少部分人获得更深优惠”采用以下模型：

```text
用户资格（会员/新人/标签/白名单）
  × 优惠自身的叠加策略
  × 商品行作用范围
  × 优惠层级和互斥组
  × 预算、次数与最低实付保护
= 可解释的优惠组合
```

系统不得采用全局 `canStackCoupons=true` 之类的无限叠加开关。特殊用户只能使用明确授权的特殊优惠组合，并继续受预算、次数、商品范围、最大减免和最低实付限制。

## 3. 证据标签

本文档统一使用以下标签：

- `JD-FACT`：京东公开规则直接明确的事实。
- `JD-HIST`：京东已标注为历史版本的规则，只用于理解演变。
- `INFERENCE`：根据公开规则作出的工程推导，不宣称是京东内部实现。
- `WSX-DECISION`：为 WebShopX 确定的产品或技术规则。
- `OPEN`：实现前仍需要项目所有者确认的产品选择。

## 4. 实施边界

- 首次实现应覆盖完整数据模型与确定性计算协议，但可以分阶段开放界面。
- 正向销售订单参与优惠；回收订单默认不参与。
- 团购凭证默认属于独占促销，除非后台显式配置例外。
- `SHOP_COIN` 与 `GAME_COIN` 分别计算，优惠不能跨币种抵扣。
- 现有兑换码继续表示“向钱包发放货币”，不与订单优惠券合并。
- 所有优惠金额均使用非负整数；比例使用基点，`10000` 表示 100%。
- 当前官方商城订单只有一个商品行，但数据和算法按多商品行设计，为未来购物车保留确定行为。

## 5. 评审时必须确认

下列 `OPEN` 项不会影响文档主体，但进入实施前应由维护者定稿：

1. 默认最低实付为 `0`、`1`，还是按币种配置。
2. 用户是否可以手动选择非最优优惠组合；本文默认允许，系统同时推荐最优组合。
3. 优惠券过期后因取消订单返还，是保持过期还是给予补偿期；本文默认保持过期。
4. 第一阶段是否开放自动领券；本文设计支持，但建议先开放手动领取和定向发放。
5. 商品分类是新建官方商城分类体系，还是先用商品集合；本文技术设计支持两者，首期可用集合。

## 6. 完成定义

只有当系统可以对任一结算返回下列信息，才算优惠系统完成：

- 每个候选优惠为什么可用或不可用；
- 为什么选中当前组合，以及被排除组合的冲突原因；
- 每个价格阶段、每个商品行分别减免多少；
- 订单最终应付、最低实付和预算消耗；
- 取消或退款时退多少钱、退哪些权益、为什么。
