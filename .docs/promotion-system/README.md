## 1. 给执行 Codex 的指令

如果你只被告知本目录位置，请从本文开始，按“阅读顺序”读完全部文件，再修改代码。不得依赖创建这些文档时的聊天上下文。

你的任务是完整实现：

```text
购物车
+ 官方商城与玩家市场的多商品结算
+ 平台、卖家和共同承担的优惠
+ 自动最优组合与少量资格用户的特殊叠券
+ 可购买、兑换和定向授予的会员系统
+ 回收、充值、团购、直接交易与拍卖的差异化权益
+ 价格快照、分账、退款、退券、权限、审计与管理界面
```

只完成表结构、后端、页面壳、单一券种或单一业务域均不算完成。开发可以分检查点推进，但最终验收是一个完整系统。

## 4. 硬性要求与自主空间

### 4.1 不得自行改变

- 优先级：用户简单 > 功能完整 > 管理者简单。
- 用户默认零操作获得合法最低价，价格上涨必须重新确认。
- 购物车、多商品、多卖家和多币种子订单属于正式范围。
- 优惠覆盖全域，但不同经济方向使用不同权益类型。
- 平台与卖家优惠的成本必须独立、守恒、可审计。
- 特殊用户只能解锁指定叠加槽位，不能任意无限叠券。
- 建设完整会员体系，支持购买、兑换、定向授予。
- 默认最低实付为每币种 1 个最小单位；零元必须显式授权与审计。
- 报价、下单、重试、退款必须使用可重放的价格快照。
- 货币、预算、库存、券、资格和结算必须具备事务、幂等和并发保护。
- 玩家卖家不能操作他人商品、成本、会员、平台券或平台预算。
- 超级管理员拥有所有新增管理权限；其余沿用现有细粒度权限体系。
- SQLite 与 MySQL/MariaDB、单机与现有 Redis 集群模式都必须保持支持。
- Web UI 所有用户可见文字进入现有 Vue I18n，中文和英文同时交付。

### 4.2 可以自主优化

执行者可以在不破坏上述要求的前提下：

- 调整包名、类名、表拆分和组件边界；
- 用更可靠或更简单的确定性算法替代本文建议；
- 发现现有代码更合适的复用点后调整集成方案；
- 增加必要索引、缓存、后台辅助页面、指标和测试；
- 调整内部开发顺序；
- 修复本文的小错误、补充遗漏并同步更新相关文档。

如果改动会改变用户行为、卖家收入、平台成本、退款结果、权限边界、业务范围或已批准优先级，必须停止并请求项目所有者确认。

## 5. 当前仓库基线

### 5.1 后端

- 路径：本文档所在仓库根目录。
- Java 插件，主要代码位于 `src/main/java/com/webshopx/`。
- HTTP 入口集中在 `EmbeddedWebServer`。
- 数据库支持 SQLite 与 MySQL/MariaDB；schema 位于 SQLite 资源、MySQL provider 和 `SchemaManager` 迁移逻辑中。
- 当前官方商品由 `ProductService` 报价，`OrderService` 下单与退款。
- 当前玩家市场由 `MarketService` 管理出售、收购、拍卖、动态定价、费用、交付和退款。
- `WalletService` 使用业务键保证钱包流水幂等。
- `AdminService`、`AdminPermission`、`AdminAuditService` 已提供权限和审计基础。
- `ClusterEventBusService`、Redis 配置和运行时配置服务可用于缓存失效与集群同步。
- `RechargeService` 与支付桥处理法币充值；`RedeemCodeService` 当前只发放钱包货币。

### 5.2 前端

- 相邻目录：`../webshopx-web`。
- Vue 3、Vite、Vuetify、Vue Router、Vue I18n、Axios。
- 商城、市场、订单、账户和管理页面位于 `src/pages/`。
- API 封装位于 `src/api/`。
- 必须先阅读该仓库 `AGENTS.md`；新增中英文资源分别写入 `src/i18n/app/` 与 `src/i18n/admin/`。
- 不要直接编辑后端仓库被忽略的编译后 Web 资源；后端构建会从相邻前端同步产物。

## 6. 完成定义

完成时必须满足：

- 登录用户可以把官方商品和可购物车化的市场出售挂单加入购物车，一次确认完成多子单结算。
- 系统自动选择最低价，用户可查看或更换合法组合。
- 平台管理员能创建全域活动、券、商品集合、用户人群、会员计划和权益。
- 玩家卖家能用简单模板为自己的直接出售挂单创建自费优惠，并看到成本和效果。
- 会员可通过购买、兑换或定向授予获得，权益到期、撤销和退款行为正确。
- 回收、充值、团购和拍卖使用文档规定的差异化权益而不是错误套用减价券。
- 每笔订单能解释基础价、卖家优惠、平台优惠、费用、实付、卖家应收和平台成本。
- 并发不会超卖、超预算、重复核销、重复退款或重复授予首购/会员资格。
- 部分交付和部分退款精确使用冻结分摊；累计全退等于原实付。
- 管理、卖家、用户权限隔离正确，关键操作均有审计。
- 新旧订单兼容，升级与紧急关闭演练通过。
- 后端和前端规定的所有检查、构建和测试通过。
- 本目录同步反映最终实现，不能让代码和规格长期分叉。

## 7. 明确排除

以下不属于本次必交付，除非实现时它们成为满足硬性要求的必要条件：

- 机器学习实时千人千券；
- 广告投放或推荐算法；
- 外部商家的法币清结算与开票；
- 优惠券用户间转赠和二级交易；
- 自动续费会员；
- 跨币种汇率凑单；
- 让拍卖竞价中途因个人优惠改变公开出价排名。
