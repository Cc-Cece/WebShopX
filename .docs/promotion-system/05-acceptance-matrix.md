# 完成定义与验收测试矩阵

## 1. 验收规则

- 测试金额使用整数并断言完整分摊，不只断言最终总额。
- 纯计算核心必须拥有高覆盖单元/属性测试，不连接数据库。
- SQLite 与 MySQL/MariaDB 分别运行 schema 与业务 SQL 测试。
- 并发测试断言数据库最终状态、钱包/资金账本和事件，而非只看响应。
- API 测试断言 error code/details、权限、幂等和归属。
- 前端通过 i18n、类型、构建及端到端人工/自动浏览器验证。
- 以下矩阵是最低集合；实现中发现的缺陷必须补回归测试和文档。

## 19. 性能、安全与属性测试

- 20 行/50 候选达到技术目标。
- 无 N+1 规则/资格查询。
- 券码不落明文，错误尝试限速。
- JSON 规则大小/深度/枚举严格校验。
- 随机属性测试验证金额非负、守恒、分摊、全退、确定性、幂等。
- 随机生成多卖家 funding，验证平台优惠不降卖家应收、卖家优惠不耗平台预算。
- 故障注入覆盖钱包、预算、库存、快照、交付和事件边界。

## 20. 最终上线门槛

必须全部满足：

- 本矩阵相关自动测试和浏览器验证通过；
- 后端 `gradlew.bat test -PskipFrontendResourceTests=true` 通过，并运行与改动风险相称的完整构建/静态检查；
- 前端四个强制命令全部通过；
- SQLite、MySQL/MariaDB 和集群并发完成验证；
- 无优惠路径回归一致；
- 价格快照与资金核对工具可用；
- 紧急停止和恢复演练；
- 历史订单退款演练；
- 用户、卖家、管理员三个视角完成桌面/移动验收；
- 文档、API、schema、i18n 和实现一致；
- 工作区无无关改动，提交历史可审阅。
