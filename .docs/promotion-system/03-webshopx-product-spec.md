# WebShopX 全域优惠、购物车与会员产品规格

## 1. 产品原则

### 1.1 用户简单

- 默认自动加入购物车、自动算最低价、一次确认结算。
- 商品页只突出到手价和最关键条件；完整规则按需展开。
- 系统主动解释差额和不可用原因，不让用户猜叠加顺序。
- 价格变贵必须确认；价格变便宜可显示新优惠后继续确认。

### 1.2 功能完整

- 所有交易域接入统一规则、资格、资金、快照和审计底座。
- 多商品、多卖家、多币种、动态价格、部分交付和部分退款均有确定行为。
- 完整不等于所有业务能混在一张购物车；不同经济方向必须保持正确边界。

### 1.3 管理简单

- 平台管理员和玩家卖家优先使用模板。
- 高级字段折叠，模拟器把内部复杂规则转成实付/应收/成本结果。
- 危险配置由系统阻止或明确警告，不依赖管理者记忆规则。

## 2. 角色

| 角色 | 能力 |
|---|---|
| 游客 | 浏览公开商品与活动；不能持久购物车、领券或结算 |
| 登录用户 | 购物车、领券、结算、会员、订单与售后 |
| 玩家卖家 | 在登录用户能力上管理自己的挂单促销、券和效果 |
| 管理员 | 依现有权限管理平台活动、会员、用户、订单或市场 |
| 超级管理员 | 拥有全部新增权限和紧急控制能力 |

玩家卖家不是后台管理员，使用玩家端“卖家中心”；不得进入平台管理 API。

## 3. 购物车

### 3.1 可加入对象

- 官方商城正向销售商品，包括普通交付、快照物品、药水效果、团购凭证和会员商品；
- 玩家市场 `SELL + DIRECT` 且当前可购买的挂单；
- 支持直接买断的特殊拍卖算法只有在其行为等价于固定即时购买时才能加入，否则走独立拍卖流程。

### 3.2 不加入同一购物车

- 官方回收；
- 玩家市场 `BUY` 收购单履约；
- 竞价拍卖出价；
- 法币充值；
- 邮箱领取、退款或兑换码操作。

这些业务仍接入统一权益系统，但使用自己的报价/提交页面。

### 3.3 持久化与合并

- 购物车只对登录用户开放，以服务端数据为准。
- 同一来源、同一交付选择且可合并的商品增加数量；市场挂单以 listing ID 唯一。
- 每次修改返回新 `cartVersion`，并发旧版本修改返回冲突和最新购物车。
- 删除、数量变更和清空均为幂等操作。
- 购物车不保留库存、价格、优惠、会员资格或市场挂单状态。

### 3.4 失效行

商品下架、市场售罄、卖家暂停、价格变化、超限购或资格变化时，保留该行并标记原因，允许删除或刷新；不能静默删除。

### 3.5 多币种

购物车可以同时展示两种钱包币种。优惠和门槛按币种分别计算。结算页按币种显示余额、应付和不足状态。

## 4. 结算

### 4.1 用户流程

1. 用户选择要结算的购物车行，默认全选有效行。
2. 系统生成 `AUTO_BEST` 报价。
3. 页面显示按卖家/业务分组的商品、优惠总额、各币种应付和交付方式。
4. 用户可展开“更换优惠”，固定某张券或关闭可选优惠。
5. 用户确认后提交 `quoteId + idempotencyKey`。
6. 服务端事务内复核；有变更则返回差异，不扣款。
7. 成功后移除已购买购物车行并进入父订单详情。

### 4.2 原子性

一次结算默认全成功或全失败。官方商品和玩家市场交付都先写队列，不在数据库事务中直接执行 Minecraft 操作，因此可以原子创建。

若未来出现不可事务化的外部子单，不得自行改成部分成功；需要新增补偿事务设计并取得方向确认。

### 4.3 拆单

父交易按以下维度拆 `OrderGroup`：

- 币种；
- 业务域（官方/市场）；
- 玩家卖家；
- 履约方式或服务器要求；
- 独占业务（如团购凭证需要独立组）。

平台级优惠可跨多个卖家组分摊，但不能跨币种。用户订单页先显示父交易，再展开子订单。

### 4.4 交付方式

每行沿用现有即时/领取模式能力。若同一组含不同方式，允许再拆组。优惠门槛以提交时整次同币种有效行计算，不因履约拆组而丢失；分摊冻结到行。

## 5. 商品与价格展示

- 列表卡片展示基础价、预计到手价、会员提示和最多两个营销标签。
- 动态定价商品明确标记“价格可能变化”。
- 商品详情展示自动优惠、可领券、会员权益、有效期和适用范围。
- 玩家市场卡片展示卖家名称，并区分“卖家优惠”“平台补贴”。
- “预计到手价”只采用当前用户当前数量能实际满足的优惠；不能用必须凑单但当前未满足的价格冒充。
- 对可凑单优惠显示“再购 X 可减 Y”，但不自动加入其他商品。

## 6. 优惠券

### 6.1 获取方式

- 用户主动领取；
- 满足条件自动发放；
- 输入券码后绑定账户；
- 平台管理员定向/批量发放；
- 玩家卖家向符合其范围的用户发放卖家券；
- 订单完成奖励；
- 会员权益周期发放。

券码只把券绑定到当前用户，不允许多人匿名在支付时直接共享同一个可消费实例。

### 6.2 我的优惠券

分页：可用、暂不可用、已使用、已过期/撤销。每张券显示：

- 优惠和门槛；
- 平台或卖家来源；
- 商品/业务范围；
- 有效期；
- 可否与会员/卖家/平台优惠共同使用；
- 去使用入口；
- 不可用的主要原因。

### 6.3 生命周期

`AVAILABLE -> RESERVED -> CONSUMED`，并支持 `RELEASED/RETURNED/EXPIRED/REVOKED/CLOSED`。状态定义和转换见第 10 号文档。

## 7. 平台促销

平台管理员可以创建：

- 官方商品直降、固定价、满减、满折、多件和阶梯优惠；
- 跨玩家卖家的平台满减/券；
- 指定业务、商品集合、标签、服务器、渠道和用户人群活动；
- 会员价、会员券和特殊叠券资格；
- 回收加成、收购奖励、充值赠币/法币优惠；
- 拍卖成交后的平台费用权益；
- 补偿券、订单奖励券和后置返币。

每个活动配置：名称、展示说明、时间、范围、人群、规则、叠加、预算、库存、次数、最低实付、退款/返券、资金承担和报表标签。

## 8. 玩家卖家促销

### 8.1 卖家范围

“店铺”即 `seller_user_id`。卖家只能选择自己拥有、可正常出售的 `SELL + DIRECT` 挂单。

### 8.2 简单模板

- 单品直降；
- 指定挂单满额减；
- 指定挂单满件折；
- 卖家优惠券。

模板自动设置卖家承担、适用范围、默认互斥和安全上限。高级选项可设置有效期、发行量、每用户次数、最大预算和与其他卖家优惠的关系。

### 8.3 限制

- 不能覆盖他人挂单；
- 不能创建平台或会员权益；
- 不能跨卖家范围；
- 不能承担平台成本或要求其他卖家承担；
- 不能突破平台配置的最低成交基数、最大折扣、最长活动期和发行量；
- 挂单暂停/下架/售罄后，新使用自动停止；
- 卖家被限制市场权限时，其未结束促销一并暂停。

### 8.4 卖家中心

提供促销列表、创建模板、券发放、预算/让利、成交额、使用订单、暂停和结束。所有金额同时展示“买家少付”和“我的应收减少”，避免误解。

## 9. 优惠资金承担

- 平台优惠消耗平台活动预算，不降低玩家卖家应收。
- 卖家优惠降低卖家成交基数和应收，不消耗平台预算。
- 共同承担按活动固定比例/固定额拆分。
- 平台可配置卖家单次和周期最大让利，但不得替卖家静默扩大。
- 管理和订单页面可查看平台成本、卖家成本和资金账本业务键。

平台对玩家市场补贴会在封闭钱包中产生币，必须记入平台促销资金账户；不能只多给卖家而不记成本。

## 10. 会员系统

### 10.1 会员计划与等级

管理员配置：

- 计划代码、名称、说明、等级和排序；
- 固定期限、自然期或永久有效；
- 是否允许叠加时长、升级和降级；
- 购买商品、兑换码和定向授予方式；
- 退款撤销、宽限期和到期规则；
- 权益包版本。

一个用户可以拥有多个不同计划；同计划同时只有一个有效等级实例。续期/升级行为必须由计划规则明确。

### 10.2 获取方式

**购买：** 使用正式 `MEMBERSHIP` 官方商品，通过正常购物车和订单交付，在配置的付款/交付状态授予资格。

**兑换：** 新的权益兑换码绑定会员授予动作。现有钱包充值兑换码保持兼容，不直接改语义。

**定向授予：** 有权限管理员选择用户、计划、等级、时间和原因；可以延长、替换或撤销，均审计。

### 10.3 权益

- 官方/市场/回收/充值的专享规则；
- 会员专享券及周期发放；
- `MEMBER_COUPON` 特殊叠券槽位；
- 手续费减免；
- 会员专属商品/活动；
- 未来非价格权益通过通用 entitlement code 扩展。

权益按版本冻结到订单。会员过期不影响历史价格和退款。

### 10.4 循环保护

默认使用下单前已有会员权益；本单购买后才生效的会员不能优惠同一笔会员商品。续费专享活动可以显式允许现有会员权益。

## 11. 官方商城特殊业务

### 11.1 团购凭证

- 可以加入购物车，但默认独占为单独子订单；
- 默认只允许团购活动价或专用券；
- 普通平台券、会员券是否可用由管理员显式开启；
- 退款时未消费凭证按冻结实付退，已消费沿用现有禁止/策略处理。

### 11.2 官方回收

- 不进入购物车；使用专门回收报价。
- 支持平台回收加成、数量阶梯、会员加成和加成券。
- 实际移除物品后才核销奖励；失败必须回滚资格/预算或恢复物品。

### 11.3 动态定价

- 优惠在冻结动态 P0 后计算。
- 下单复核失败返回动态价格变化。
- 促销不能直接修改需求分；动态事件仍由成功业务数量驱动。

## 12. 玩家市场特殊业务

### 12.1 直接出售

完整支持购物车、卖家优惠、平台优惠、会员权益和分账。

### 12.2 收购挂单

- 不进入购物车，由卖方向挂单履约。
- 支持平台加成；收购方自费加成必须在挂单创建/编辑时增加托管最大负债。
- 若实际奖励规则变化超过托管，挂单暂停并要求补充，而不是让系统透支。

### 12.3 拍卖

- 出价不使用商品折扣券或个人会员价。
- 允许公开统一的拍卖活动规则，只要所有竞拍者同条件且页面明确。
- 会员/平台权益可以在成交后减免费用或发放后置奖励，不改变中标金额。
- 卖家不能对拍卖创建私有券。

### 12.4 供货箱与自动补货

当挂单是系统供货模式时，资金承担主体仍由挂单所属卖家/平台身份决定。自动补货不恢复促销预算，也不改变活动版本。

## 13. 充值优惠

- 充值页面先根据金额、支付方式、会员和券生成法币报价与预计到账。
- 用户明确看到“原应付、支付优惠、实际支付、基础到账、额外赠送”。
- 创建支付单后法币报价冻结；支付提供方回调金额必须一致。
- 充值券在支付成功时消费，创建失败/取消/过期时释放。
- 赠币分独立钱包流水；退款时按活动策略扣回或转人工。
- 不得允许钱包币优惠券抵法币，除非未来另行批准混合支付。

## 14. 活动与规则生命周期

```text
DRAFT -> SCHEDULED -> ACTIVE -> PAUSED -> ACTIVE
  |          |           |          |
  +-> ENDED  +-> ENDED   +-> TERMINATED
```

- 沿用现有管理制度，不强制双人审批。
- 发布后关键规则不可原地修改；修改创建新版本。
- 活动可由有权限管理员暂停/恢复/提前结束。
- 卖家促销无需平台逐条审批，但必须通过平台限制；管理员可暂停。
- 历史版本永久可供订单解释，不能物理删除。

## 15. 管理后台

### 15.1 导航

新增“营销与会员”管理域：

- 活动；
- 优惠券；
- 商品集合；
- 用户人群/资格；
- 会员计划与权益；
- 平台资金账户；
- 模拟器；
- 报表与审计。

### 15.2 创建向导

1. 选择业务目标和模板；
2. 设置优惠；
3. 选择商品/卖家/业务范围；
4. 选择用户资格；
5. 确认叠加；
6. 设置预算、次数和最低实付；
7. 设置退款/返券/奖励撤销；
8. 模拟代表性订单；
9. 发布。

### 15.3 模拟器

输入用户、时间、服务器、商品/挂单、数量、币种和券，输出每层金额、用户实付、卖家应收、平台成本、资金守恒和不可用原因。无任何核销副作用。

## 16. 权限

新增建议权限：

- `PROMOTION_VIEW`, `PROMOTION_MANAGE`
- `COUPON_MANAGE`, `COUPON_GRANT`, `COUPON_COMPENSATE`
- `MEMBERSHIP_VIEW`, `MEMBERSHIP_MANAGE`, `MEMBERSHIP_GRANT`
- `PROMOTION_FINANCE_VIEW`
- `SELLER_PROMOTION_MODERATE`
- `PROMOTION_EMERGENCY_STOP`

`SUPER_ADMIN` 继续通过 `EnumSet.allOf` 获得全部权限。默认角色模板按现有职责扩展：

| 角色 | 新增默认权限 |
|---|---|
| `SHOP_ADMIN` | `PROMOTION_VIEW/MANAGE`、`COUPON_MANAGE/GRANT/COMPENSATE`、`MEMBERSHIP_VIEW/MANAGE/GRANT`、`PROMOTION_FINANCE_VIEW` |
| `MARKET_MODERATOR` | `PROMOTION_VIEW`、`SELLER_PROMOTION_MODERATE` |
| `SUPPORT_ADMIN` | `PROMOTION_VIEW`、`MEMBERSHIP_VIEW` |
| `AUDITOR` | `PROMOTION_VIEW`、`MEMBERSHIP_VIEW`、`PROMOTION_FINANCE_VIEW` |
| `SUPER_ADMIN` | 全部权限，包括 `PROMOTION_EMERGENCY_STOP` |

自定义权限 JSON 必须兼容新枚举；旧 JSON 缺少新值时按“不拥有”处理，不得反序列化失败。默认模板不等于硬编码授权，现有显式权限覆盖机制保持有效。紧急停止默认只授予超级管理员，其他角色必须由超级管理员显式授予。

玩家卖家权限通过资源所有权和平台市场限制控制，不加入 `AdminPermission`。

## 17. 售后

- 父订单汇总展示，退款实际发生在可退款子订单/商品单位。
- 官方、市场和团购继续遵守各自交付/退款政策，但金额来自统一快照。
- 退款结果分开列出钱包退款、卖家结算冲回、平台预算冲回、返券、会员/奖励处理。
- 返券或撤销奖励失败不能导致金额账本悄悄不一致；事务回滚或转人工并明确状态。

## 18. 通知

复用通知中心，至少覆盖：券到账/临期、会员生效/临期/到期、活动暂停、卖家预算耗尽、价格变化、退款返券和人工处理。批量临期通知必须有频控。

## 19. 报表

平台报表：发/领/用/过期漏斗、优惠成本、卖家让利、补贴、会员收入/活跃、业务域、特殊叠券、退款与异常。

卖家报表：促销成交额、让利、使用订单、券漏斗和活动状态，只能看到自己的数据。

没有对照实验时不得把优惠订单额宣称为增量收入。
