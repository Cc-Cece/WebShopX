# WebShopX 优惠系统产品规格

## 1. 产品目标

优惠系统用于在不直接修改商品永久标价的前提下，精确控制价格、人群、时间、预算和叠加关系，并让管理员能够追踪每一笔优惠成本。

成功标准：

- 管理员能建立从普通满减到会员叠券的完整规则；
- 用户在提交订单前看到确定的价格明细和不可用原因；
- 特殊用户获得更深优惠时，系统能说明其资格来源；
- 超发、并发首单、重复用券、规则中途变更不会造成错误扣款；
- 退款金额和退券结果可以从订单快照重放。

## 2. 范围

### 2.1 包含

- 自动促销、可领取券、兑换券码和定向发券；
- 固定减免、比例折扣、满减、满折、阶梯和多件优惠；
- 全场、商品、商品集合、产品类型与用户人群范围；
- 普通互斥、跨层叠加、会员特殊槽位和组合白名单；
- 活动库存、券库存、预算、领取/使用频率和最低实付；
- 价格预览、最优组合、手动选择、核销、取消、退款和返券；
- 后台权限、审批、审计、报表和紧急停用。

### 2.2 不包含或暂缓开放

- 基于机器学习的实时千人千券；
- 真实法币支付立减、银行卡活动；
- 第三方商家之间的资金结算；
- 物流运费优惠（保留模型，当前没有运费则不开放）；
- 积分系统本身（保留 `POINTS_OFFSET` 接入层）；
- 玩家市场交易默认不参与官方商城优惠。

## 3. 用户角色

| 角色 | 能力 |
|---|---|
| 普通用户 | 查看活动、领取券、查看自己的券、预览和选择优惠 |
| 资格用户 | 在普通能力上获得会员/新人/白名单等专属优惠槽位 |
| 客服 | 查询优惠计算轨迹、处理返券或发放补偿券，不可修改通用活动 |
| 营销管理员 | 创建草稿、配置范围/人群/库存/预算、查看效果 |
| 审批管理员 | 审核高风险优惠、发布和停用活动 |
| 审计员 | 只读查看规则版本、发券、核销、预算和管理操作 |
| 超级管理员 | 紧急停用、权限配置及极端修复操作 |

## 4. 用户人群与资格

### 4.1 内置人群

- 所有已登录用户；
- 新注册用户；
- 全局首单用户；
- 指定商品集合首购用户；
- 回流用户（指定天数无完成订单）；
- 会员等级；
- 用户标签；
- 明确用户 ID / MC UUID 白名单；
- 指定服务器或入口渠道用户。

### 4.2 标签和资格来源

资格必须保存来源：

- `SYSTEM_DERIVED`：订单历史等自动计算；
- `MEMBERSHIP`：会员系统授予；
- `ADMIN_GRANTED`：管理员定向授予；
- `CAMPAIGN_GRANTED`：活动参与产生；
- `IMPORT`：经审计的批量导入。

管理员手动资格必须包含原因、开始/结束时间、操作者和审计记录。资格撤销不得追溯改变已完成订单。

### 4.3 特殊叠券用户

系统提供资格代码 `MEMBER_STACKING`、`CAMPAIGN_STACKING`、`COMPENSATION_STACKING`。每个代码只解锁对应槽位或组合，不代表任意券可叠加。

示例：

- 用户 A 有 `MEMBER_STACKING`，可用普通商品券 + 会员专享券；
- 用户 B 只有普通会员折扣，没有会员叠券资格，仍只能使用普通券；
- 用户 C 收到补偿券，只有该补偿券模板声明兼容普通券时才能叠加。

## 5. 活动模型

### 5.1 活动状态

```text
DRAFT -> PENDING_APPROVAL -> SCHEDULED -> ACTIVE -> ENDED
  |             |               |          |
  +-> CANCELLED +-> REJECTED    +-> PAUSED +-> TERMINATED
```

- 已发布版本不可原地修改关键价格规则；修改产生新版本。
- `PAUSED` 阻止新预览和下单，不影响已成功订单。
- `TERMINATED` 是不可恢复的提前结束。
- 到时启停由任务驱动，但结算仍以数据库时间和状态为准。

### 5.2 活动配置

每个活动包含：

- 基本信息：名称、内部备注、用户说明、时间、优先级；
- 优惠内容：类型、档位、金额/比例、最大减免；
- 商品范围：包含、排除和范围版本；
- 人群范围：领取资格与使用资格；
- 叠加关系：层、槽位、互斥组、兼容白名单；
- 财务护栏：总预算、每日预算、发行量、最低实付；
- 频控：每用户/UUID/周期领取和使用次数；
- 售后：返券、资格恢复、是否参加价格保护；
- 展示：标题、标签、规则说明、倒计时和排序。

## 6. 优惠券模型

### 6.1 获得方式

- `CLAIM`：用户主动领取；
- `AUTO_GRANT`：满足条件自动到账；
- `CODE`：输入兑换码后绑定账户；
- `ADMIN_GRANT`：管理员定向发放；
- `BATCH_GRANT`：经审批的批量发放；
- `ORDER_REWARD`：订单完成后发放，用于下次购买。

券码只负责把券实例绑定给用户，不允许直接在结算时匿名消费公共码，从而避免共享码并发和归属不明。

### 6.2 用户券状态

- `AVAILABLE`
- `RESERVED`
- `CONSUMED`
- `RELEASED`
- `RETURNED`
- `EXPIRED`
- `REVOKED`
- `CLOSED`

状态变化必须进入不可变事件日志。列表页状态可以由实例当前状态和时间计算，但历史事件不能覆盖。

### 6.3 我的优惠券

用户端分为：

- 可使用：展示金额、门槛、有效期、适用商品和叠加提示；
- 暂不可用：展示最主要原因和去使用入口；
- 已使用；
- 已过期/已撤销。

不得只显示营销名称；必须提供简明规则摘要，例如：

```text
满 100 减 20 · 指定官方商品 · 可与会员专享券叠加
2026-08-31 23:59 前有效 · 每个订单限 1 张
```

## 7. 商品页与结算体验

### 7.1 商品页

- 展示当前用户可得的预估到手价；
- 展示正在生效的自动优惠；
- 展示可领取券和已领取状态；
- 对会员或首购专享价明确标注身份条件；
- 预估价旁说明“最终以结算为准”。

### 7.2 报价/结算

结算区展示：

- 商品基础金额；
- 动态价格或活动价变化；
- 促销优惠；
- 优惠券优惠；
- 权益抵扣；
- 最终应付；
- 已选择组合与其他可选组合；
- 不可用优惠及原因。

系统默认勾选最优组合。用户改变选择后必须重新报价；提交订单携带 `quoteId`，不允许客户端自行提交优惠金额。

### 7.3 报价变化

报价失效时返回新的报价和变化原因：

- 商品动态价格变化；
- 活动开始/结束或暂停；
- 库存/预算耗尽；
- 用户券在另一会话使用；
- 首购资格被另一订单消耗；
- 规则版本变化。

系统不得在最终提交时静默提高应付金额并继续扣款。

## 8. 后台工作台

### 8.1 列表

活动/券模板列表至少支持：

- 状态、类型、时间和负责人筛选；
- 总预算、已预留、已消耗和剩余；
- 发行、领取、核销、退款/返券数量；
- 订单优惠额和受益用户数；
- 快速暂停，但发布和终止要求确认。

### 8.2 创建向导

推荐步骤：

1. 选择促销或券；
2. 设置优惠内容与阶梯；
3. 选择商品范围；
4. 选择用户资格；
5. 配置叠加关系；
6. 配置预算、库存、次数和最低实付；
7. 设置取消/退款/返券规则；
8. 使用模拟订单验证；
9. 提交审批和发布。

### 8.3 规则模拟器

管理员可输入用户、商品、数量、币种和时间，获得完整计算轨迹。模拟不得消耗券、预算或资格。高风险配置必须通过内置边界案例后才能发布。

### 8.4 风险提示

以下情况阻止发布或要求高级审批：

- 折扣后可能低于全局最低实付；
- 百分比券没有最大减免；
- 特殊槽位兼容范围过宽；
- 预算无限且发行量无限；
- 补偿券可批量发放；
- 活动覆盖回收/团购等默认排除类型；
- 修改已生效活动导致用户可见价格显著变化。

## 9. 权限与审批

建议新增权限：

- `PROMOTION_VIEW`
- `PROMOTION_EDIT`
- `PROMOTION_APPROVE`
- `PROMOTION_PUBLISH`
- `PROMOTION_EMERGENCY_STOP`
- `COUPON_GRANT`
- `COUPON_COMPENSATE`
- `PROMOTION_AUDIT_VIEW`

发布、扩大商品范围、提高减免、放宽叠加和提高预算属于高风险操作。生产环境默认执行双人原则：创建者不能审批自己的高风险变更。

补偿发放必须填写关联订单或工单、原因和有效期。批量发放需要上传预览、去重结果和影响人数后再确认。

## 10. 预算、库存和频控

### 10.1 三种独立限制

- **发行库存**：最多产生多少张用户券；
- **核销次数**：最多成功使用多少次；
- **优惠预算**：最多实际承担多少优惠金额。

三者不得混用。预算以最终实际减免预留，取消或满足退款恢复条件时释放/冲回。

### 10.2 频率维度

- 每用户总次数；
- 每 MC UUID 总次数；
- 每日/每周/活动周期次数；
- 每商品或商品集合次数；
- 全局并发领取速率。

## 11. 售后体验

订单详情展示原始金额、优惠明细、实付及预计退款。退款结果分开显示：

- 退回钱包金额；
- 已返还优惠券；
- 未返券及原因；
- 已恢复或未恢复的首购/活动资格。

管理员可以人工补偿，但不能修改历史订单价格快照。补偿产生新的券或钱包业务流水。

## 12. 报表

基础报表：

- 发券、领券、核销和过期漏斗；
- 优惠预算预留/消耗/释放；
- 活动订单数、优惠总额和平均优惠；
- 普通与资格用户的使用分布；
- 特殊叠券订单及平均叠加层数；
- 取消率、退款率、返券率；
- 预算/库存耗尽时间；
- 规则冲突与报价失效原因分布。

报表中的“收入提升”“转化提升”需要实验或对照组才能成立；不能仅凭使用优惠的订单量宣称增量收益。

## 13. 分阶段开放

完整规则先落库，界面按以下顺序开放：

### 阶段 A：底座

- 价格快照、报价 API、固定/比例券；
- 商品集合、人群、预算、库存、普通互斥；
- 下单核销、取消/退款和后台审计。

### 阶段 B：完整促销

- 自动满减/满折、阶梯、多件优惠；
- 自动最优组合、规则模拟器；
- 会员特殊槽位和定向发券。

### 阶段 C：运营增强

- 首购/回流、订单奖励券、批量发放；
- 报表、实验分组和价格保护；
- 未来积分与费用优惠接入。

阶段划分只控制上线顺序，不允许阶段 A 使用未来无法兼容的临时金额字段。
